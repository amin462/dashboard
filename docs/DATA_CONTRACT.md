# DATA CONTRACT (source of truth สำหรับทุก agent)

ฐานข้อมูล: `supabase/schema.sql` → ตาราง `survey_responses` (1 แถว = 1 คำตอบ, ค่าดิบเป็นข้อความไทยตรงกับ Google Form)
ทุกการนับ/ร้อยละ ต้องคำนวณใน `web/lib/survey/` ที่เดียว (pure functions + vitest) UI ห้ามคำนวณเอง

## 2. กฎทำความสะอาด (ทำใน `normalize.ts`)
1. **ฐานวิเคราะห์ = `is_complete = true`** (ผ่านคัดกรอง 2 ข้อ + ยินยอม + ตอบข้อบังคับครบ) แถวอื่นนับแยกเป็น "ไม่ผ่านคัดกรอง/ไม่ยินยอม/ไม่ครบ" ในหน้าคุณภาพข้อมูล
2. ค่าที่ไม่อยู่ในรายการ → หมวด `อื่น ๆ` และเก็บข้อความไว้แสดงในตาราง "คำตอบอื่น ๆ" (sur02 ค่าแบบนี้มาจากคำตอบก่อนแก้ฟอร์ม)
3. sur08: split `', '` ; ถ้ามี "ไม่มีความสนใจเป็นพิเศษ" ร่วมกับข้ออื่น → ตัด "ไม่มีความสนใจเป็นพิเศษ" ทิ้ง (นับข้ออื่น) และนับเป็น "ข้อมูลขัดแย้ง" ในหน้าคุณภาพ
4. sur09 → ตัวเลข 1–5; "ยังไม่สามารถประเมินได้" ไม่นำมาเฉลี่ย แสดงจำนวนแยก
5. null/ว่าง = "ไม่ตอบ (ข้าม)" ; "ไม่ประสงค์ระบุ" / "ยังประเมินไม่ได้" = ตอบแต่ไม่ระบุ — **แยก 2 อย่างนี้เสมอ**

## 3. กฎแสดงผล (ตอบ EXP-03/04/06/11, EVA-02/05)
- ทุกกราฟ/ตาราง: ชื่อ + `ฐาน n = X คน` + `ไม่ตอบ Y` + `ไม่ประสงค์ระบุ Z` + หน่วย (คน / %)
- ร้อยละ: ตัวหาร = ผู้ตอบข้อนั้น (ไม่รวมคนข้าม) ; sur08 หลายข้อ → ตัวหาร = คนที่ตอบข้อ 8 (รวม % > 100 ได้ ต้องเขียนกำกับ)
- ทศนิยม: ร้อยละ 1 ตำแหน่ง, ค่าเฉลี่ย/SD 2 ตำแหน่ง ; แปลผลค่าเฉลี่ยตามเกณฑ์ 4.21–5.00 มากที่สุด, 3.41–4.20 มาก, 2.61–3.40 ปานกลาง, 1.81–2.60 น้อย, 1.00–1.80 น้อยที่สุด
- ข้อความประจำทุกหน้า: "ผลนี้สรุปจากผู้ตอบแบบสำรวจ ณ วัดคูหาภิมุข (เลือกตัวอย่างแบบสะดวก) ไม่ใช่ยอดนักท่องเที่ยวทั้งหมด"
- ความพึงพอใจ = ต่อ "สถานที่" ไม่ใช่ผลประเมินระบบ
- ไม่มีข้อมูลตามตัวกรอง → empty state บอกเหตุ + ปุ่มล้างตัวกรอง (EXP-08) ; กลุ่ม n < 5 แสดงเตือน "จำนวนน้อย ตีความด้วยความระมัดระวัง"

## 5. มุมมองตามประเภทธุรกิจ (4 ประเภทตามรายงานตารางที่ 4)
| ประเภท | ตัวชี้วัดหลัก | ตัวอย่างกฎข้อแนะนำ (แสดงพร้อมตัวเลข n และ %) |
|---|---|---|
| ร้านอาหารและเครื่องดื่ม | % สนใจอาหาร, ค่าใช้จ่าย, ผู้ร่วมเดินทาง, ช่วงเวลามา | ถ้า ครอบครัว เป็นกลุ่มใหญ่สุด → "จัดเมนู/ที่นั่งสำหรับครอบครัว" |
| โรงแรม/ที่พัก/โฮมสเตย์ | % สนใจที่พัก, พื้นที่พำนัก (นอกยะลา), ค่าใช้จ่าย > 1,000 | ถ้า ผู้มาจากนอกจังหวัดยะลา ≥ 40% → "โปรโมตแพ็กเกจพักค้างคืน" |
| ร้านค้า/ของฝาก | % สนใจของฝาก, ค่าใช้จ่าย, วัตถุประสงค์ | ถ้าช่วงค่าใช้จ่าย ≤ 600 บาท เป็นส่วนใหญ่ → "เน้นสินค้าราคา ≤ 300 บาท" |
| นำเที่ยว/ขนส่ง | % สนใจบริการเดินทาง/กิจกรรม, พาหนะ, ผู้ร่วมเดินทาง | ถ้า รถโดยสาร+ไม่มีรถส่วนตัว สูง → "บริการรับส่ง" |
| ทุกประเภท | SUR-06 ช่องทางรับรู้ | ช่องทางอันดับ 1 → "ลงโฆษณา/โพสต์ช่องทางนี้" |
กฎทั้งหมดอยู่ใน `web/lib/survey/insights.ts` (ข้อความ + เงื่อนไข + ค่าที่ใช้) ห้ามเขียนกฎใน UI ; ทุกข้อแนะนำต้องแสดงตัวเลขอ้างอิงและคำว่า "ข้อเสนอเบื้องต้นจากข้อมูลผู้ตอบ"

## 6. สิทธิ์ผู้ใช้ (EXP-09, ไม่ทำระบบล็อกอินเต็ม)
- **ผู้ประกอบการ (viewer):** ทุกหน้าวิเคราะห์ อ่านอย่างเดียว ไม่ต้องล็อกอิน
- **ผู้ดูแล (admin):** `/admin/*` ต้องกรอก `ADMIN_PASSCODE` (env) → ตั้ง cookie httpOnly ; ตรวจใน `proxy.ts`/middleware ; API เขียนข้อมูลใช้ `SUPABASE_SERVICE_ROLE_KEY` ฝั่ง server เท่านั้น
