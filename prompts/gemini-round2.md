## G1 — หน้าคู่มือผู้ประกอบการ `/guide`
```
อ่าน AGENTS.md, docs/DATA_CONTRACT.md ข้อ 3–5
สร้างไฟล์ใหม่ web/app/(dash)/guide/page.tsx เท่านั้น (ใช้ components เดิมได้ ห้ามแก้ไฟล์เดิม ถ้าต้องเพิ่มเมนู ให้เขียนขอใน docs/HANDOFF_NOTES.md)
เนื้อหา ภาษาไทยง่าย ๆ สำหรับเจ้าของร้าน: ระบบนี้คืออะไร, ข้อมูลมาจากไหน (แบบสำรวจ ณ วัดคูหาภิมุข), อ่านกราฟอย่างไร (ฐาน n, ไม่ตอบ, ไม่ประสงค์ระบุ, % ของข้อเลือกหลายข้อเกิน 100 ได้),
ใช้ตัวกรองอย่างไร, 4 ตัวอย่างการตัดสินใจ (ร้านอาหาร/ที่พัก/ของฝาก/นำเที่ยว) แบบ "ถ้าเห็น… → ลองทำ…", ข้อจำกัด (เลือกตัวอย่างแบบสะดวก ไม่ใช่ยอดนักท่องเที่ยวทั้งหมด), FAQ 5 ข้อ
ใช้ accordion/การ์ด อ่านบนมือถือสะดวก ผ่าน lint/tsc/build
```

## G2 — หน้าโปสเตอร์ QR แบบสำรวจ `/survey-poster`
```
สร้างไฟล์ใหม่ web/app/survey-poster/page.tsx (นอก (dash) ไม่มี sidebar) ติดตั้งได้ 1 package: pnpm -C web add qrcode.react
โปสเตอร์ A4 แนวตั้งสำหรับพิมพ์ติดที่วัด: หัวข้อ "ร่วมตอบแบบสำรวจนักท่องเที่ยว วัดคูหาภิมุข (วัดหน้าถ้ำ)", QR ใหญ่ไปที่ NEXT_PUBLIC_SURVEY_URL,
"ใช้เวลา 3–5 นาที · ไม่เก็บชื่อ เบอร์โทร อีเมล · อายุ 18 ปีขึ้นไป", โลโก้/ชื่อ มหาวิทยาลัยราชภัฏยะลา คณะวิทยาการจัดการ (ข้อความ ไม่ต้องใช้รูป), print CSS ให้พอดี 1 หน้า A4, ปุ่ม "พิมพ์" ซ่อนตอนพิมพ์
```

## G3 — เอกสารบทที่ 4 สำหรับรายงาน `docs/REPORT_SYSTEM.md`
```
อ่าน PLAN.md (สถาปัตยกรรม), supabase/schema.sql, docs/DATA_CONTRACT.md แล้ว grep โครงสร้าง web/app
เขียน docs/REPORT_SYSTEM.md ภาษาไทยแบบวิชาการ (ใช้ใส่รายงานวิจัยบทผลการพัฒนาระบบ) หัวข้อ:
1) สถาปัตยกรรมระบบ (แผนภาพ mermaid: Google Form → Apps Script → Supabase → Next.js → ผู้ใช้ 2 บทบาท)
2) การออกแบบฐานข้อมูล (ตาราง data dictionary ของ survey_responses, import_logs + การกันข้อมูลซ้ำด้วย dedupe_key)
3) ขั้นตอนตรวจสอบความครบถ้วนของข้อมูล (is_complete, กฎทำความสะอาด)
4) โครงสร้างเมนูและหน้าจอ (ตาราง หน้า → ตัวชี้วัด → รหัสข้อ SUR → ประโยชน์ต่อผู้ประกอบการ)
5) การกำหนดสิทธิ์ผู้ใช้ 6) เทคโนโลยีที่ใช้ (ตาราง) 7) ตารางเทียบ EXP-01–11 กับฟีเจอร์
ห้ามแต่งตัวเลขผลการวิจัย ใช้ "[รอผลจริง]" แทน
```
